# 事件代理

> 事件代理（Event Delegation）也叫事件委托，利用**事件冒泡**机制，将子元素的事件绑定到父元素上，通过 `e.target` 判断实际触发的子元素

## 一、问题场景

需求：给div中所有的img标签添加点击事件

```html
<div id="d1">
    <img src="./img/1.webp" alt="">
    <img src="./img/2.webp" alt="">
    <img src="./img/3.webp" alt="">
    <img src="./img/4.webp" alt="">
    <h1>标题</h1>
</div>
```

## 二、传统写法（不使用代理）

```javascript
var imgs = document.querySelectorAll("body img");
for (var i = 0; i < imgs.length; i++) {
    imgs[i].onclick = function () {
        console.log("点击了图片");
    }
}
```

**缺点**：
- 需要查找所有img元素
- 需要循环绑定事件
- 子元素动态添加时需重新绑定

## 三、事件代理写法

```javascript
d1.onclick = function (e) {
    // e.target — 触发事件的元素（可能是img、h1或#d1）
    // e.currentTarget — 事件目标this（必须是#d1）

    if (e.target.nodeName == "IMG") {
        alert("点击了图片");
    }
}
```

### 原理

```
点击img → 事件冒泡到父元素div → div的onclick触发
         ↑
    e.target = img（实际点击的元素）
    e.currentTarget = div（绑定事件的元素）
```

## 四、e.target vs e.currentTarget

| 属性 | 含义 | 示例 |
|------|------|------|
| `e.target` | 触发事件的元素（最内层） | 点击img → `e.target` = img |
| `e.currentTarget` | 绑定事件的元素（this） | 绑定在div → `e.currentTarget` = div |

```javascript
d1.onclick = function (e) {
    console.log(e.target);          // <img> 或 <h1> 或 <div>
    console.log(e.currentTarget);   // 始终是 <div id="d1">
}
```

## 五、过滤判断方式

```javascript
// 方式1：nodeName 判断标签名
if (e.target.nodeName == "IMG") { ... }

// 方式2：className 判断类名
if (e.target.className == "item") { ... }

// 方式3：classList.contains 判断包含某个类
if (e.target.classList.contains("active")) { ... }
```

## 六、事件代理的优势

| 对比项 | 传统写法 | 事件代理 |
|--------|---------|---------|
| 查找元素 | 需querySelectorAll | 不需要查找子元素 |
| 循环绑定 | 需for循环 | 不需要循环 |
| 动态元素 | 新增元素需重新绑定 | 自动生效（冒泡到父元素） |
| 内存占用 | 每个元素一个事件处理 | 只需一个事件处理 |
| 代码量 | 较多 | 较少 |

> **核心优势**：子元素动态添加时，无需重新绑定事件，新元素的事件自动冒泡到父元素

## 七、适用场景

- 列表项点击（`<ul><li>` 大量列表项）
- 表格行操作（动态添加的行）
- 图片画廊点击
- 评论区点赞/删除按钮
- 任何**子元素数量多或动态变化**的场景
