# 输入框搜索提示

> 用户在输入框打字时，每敲一个字符就发一次请求？函数防抖让请求"等一等"再发

## 一、功能分析

```
搜索提示 = 输入监听(input事件) + 请求搜索建议 + 防抖控制

核心问题:
  1. 用户连续输入时，如何避免每个字符都发请求?  → 函数防抖（计时器控制）
  2. 输入内容为空时，是否还要发请求?            → 不发，直接 return
  3. 新建议出来前，旧建议如何处理?              → 先清空 div.innerHTML
```

## 二、不加防抖的写法（反面教材）

```javascript
var input = document.querySelector("input");
var div = document.querySelector("body div");

input.oninput = function(){
    div.innerHTML = "";  // 先清空老数据
    if(input.value.length <= 0) return;  // 输入为空，不发请求

    // 每输入一个字符都会发一次请求！
    $.get("http://192.168.14.222:5000/loadMore", { page: input.value }, function(res){
        res.data.forEach(function(item){
            var p = document.createElement("p");
            p.innerText = item;
            div.appendChild(p);
        });
    });
}
```

```
用户输入 "javascript":

不加防抖:  j → 请求!  ja → 请求!  jav → 请求!  java → 请求! ...
           共发起 10 次请求，服务器压力巨大，且前面的结果已无意义
```

## 三、函数防抖的写法

**思路**：事件触发后不立即发请求，而是开启一个计时器，计时结束才发请求；如果计时期间又输入了新字符，就取消上一个计时、重新计时。

```javascript
var input = document.querySelector("input");
var div = document.querySelector("body div");
var timer;  // 定义防抖计时器

input.oninput = function(){
    clearTimeout(timer);          // 先关掉上一个计时
    timer = setTimeout(update, 1000);  // 再开启下一次计时
}

function update(){
    div.innerHTML = "";  // 先清空老数据
    if(input.value.length <= 0) return;  // 输入为空，不发请求

    // 计时结束后才发请求
    $.get("http://192.168.14.222:5000/loadMore", { page: input.value }, function(res){
        res.data.forEach(function(item){
            var p = document.createElement("p");
            p.innerText = item;
            div.appendChild(p);
        });
    });
}
```

### 防抖时间轴

```
用户输入:  j     ja    jav    java    javas    (停顿1秒)

计时器:    开启→取消  开启→取消  开启→取消  开启→取消  开启→ 1秒到!
请求:                                                    请求1次 ✓

只有最后一次输入后 1 秒内没有新输入，才会真正发起请求
```

## 四、防抖三步法

| 步骤 | 代码 | 说明 |
|------|------|------|
| 1. 定义计时器 | `var timer;` | 全局变量，保存当前计时器 |
| 2. 事件触发时先清除 | `clearTimeout(timer);` | 取消上一次未完成的计时 |
| 3. 重新开启计时 | `timer = setTimeout(update, 1000);` | 延迟后执行真正的业务函数 |

> **关键理解**：防抖不是"少触发事件"，事件照常触发，只是每次触发都重置计时器，让业务函数始终"等一等"。只有停下来超过设定时间，业务函数才真正执行。

## 五、总结

| 要点 | 说明 |
|------|------|
| 监听事件 | `input.oninput`，输入内容变化时触发 |
| 防抖核心 | `clearTimeout` + `setTimeout`，重新计时 |
| 防抖时机 | 事件触发 → 清除旧计时 → 开新计时 → 计时结束执行 |
| 空值判断 | `input.value.length <= 0` 时不发请求 |
| 适用场景 | 输入框搜索建议、窗口 resize、表单验证 |
